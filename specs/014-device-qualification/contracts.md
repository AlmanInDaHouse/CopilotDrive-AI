# Contracts

`DeviceQualification` binds a 40 hex commit and 64 hex APK hash to
`QualificationEnvironment` (HOST/EMULATOR/PHYSICAL, API, model),
`QualificationScenario` (id, preconditions, validation method), and
`QualificationResult` (CompatibilityStatus, existing EvidenceLevel, bounded code,
redacted record reference, explicit physical observation).

`CompatibilityStatus`: AUTOMATED_TESTED, EMULATOR_TESTED, PHYSICALLY_VERIFIED,
FAILED, UNSUPPORTED, BLOCKED, PENDING. PHYSICALLY_VERIFIED requires PHYSICAL,
manual observation and device/adapter/parked-vehicle evidence. Emulator instrumentation
cannot promote itself. A physical automated callback remains technical evidence only.

`PerformanceSample`: named metric, nonnegative value, iteration. Durations use
monotonic clocks; wall time only dates the run. Nearest-rank p50/p95 require n>=20
of the same metric/conditions. Memory uses KiB; no FPS/energy inference.
`AccessibilityFinding` and `RegressionRecord` link finding/scenario codes to tests;
they carry no conversations, location, VIN, credentials or contact data.

Runner JSON is a separate versioned transport contract (`schemaVersion=1`), containing
build provenance, redacted environment inventory, preconditions, method, raw numeric
samples, summaries, restoration state and fixed error codes. Physical observations are
manual records, never generated by the runner.
