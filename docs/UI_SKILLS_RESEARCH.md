## Procedencia, ejecución y riesgos

Se clonó el repositorio de Pro Max fuera del producto en `Downloads/sprint11-ui-skill-audit` y se inspeccionaron README, LICENSE, package.json, init.ts, template.ts, search.py y sus módulos core/design_system/reasoning_contract. Los scripts seleccionados consultan CSV locales; no tienen transporte HTTP, instalación de paquetes ni invocación de shell. El generador puede escribir archivos cuando se solicita `--persist`; no se utilizó esa opción. Los módulos de validación/refresco no se ejecutaron y las otras skills incluidas en el repositorio no se instalaron como herramientas del producto.

El comando publicado es `npx ui-ux-pro-max-cli init --ai codex`. Su CLI depende de chalk, commander, ora y prompts, tiene generación/copia de plantillas y una ruta legacy que descarga releases GitHub. No se ejecutó npx, npm install ni scripts de ciclo de vida. Se eligió la copia local revisada, con licencia, sin nuevas dependencias de aplicación ni instalación de Node. El instalador oficial de Codex se utilizó para las otras dos skills de Markdown; las instalaciones nuevas se descubren automáticamente desde el siguiente turno.

Las reglas del catálogo no son prueba de accesibilidad o rendimiento. Se comprobaron resultados antes de elegirlos: el generador inicial sugirió animaciones propias de una landing; se descartó. También se descartaron recomendaciones web, GSAP, coordenadas px convertidas a dp y requisitos recientes ajenos a las dependencias actuales.

Licencias revisadas en las URLs oficiales de cada repositorio, incluido `anthropics/skills/main/skills/frontend-design/LICENSE.txt`. No se redistribuye código de estas skills dentro del APK. Los símbolos de cabina son Canvas originales; las fuentes son las instaladas en Android. No hay imágenes generadas ni recursos gráficos de terceros.
